# RCA — "Estadísticas de vendedor" empty in PRODUCTION (agro-dashboard-14)

**Endpoint:** `GET /api/estadisticas/vendedores`
**Mode:** READ-ONLY diagnostic on the production MongoDB. No data was modified.
**Active run inspected:** `9a4c4e9c-2e31-430c-997d-a0e725662b97` (last successful deploy, serving traffic).

## TL;DR
The sales data is **present and intact** in production and the backend is bound to the **correct** database. The module renders empty for one reason: **no sales document in production carries a non-empty `vendedor` value**, and the `comisiones_vendedor` collection **does not exist**. The endpoint is working as designed — it explicitly skips every sale whose `vendedor` is blank (`if not vend: continue`), so with zero vendedor-tagged sales there is nothing to aggregate. This is a **DATA condition, not data loss, not a wrong-DB binding, and not a backend read/write regression.**

## 4. Database binding (checked first)
- Production backend is bound to DB **`agro-dashboard-14-erp_agricola`** (returned by the read tool, resolved server-side from the live MONGO_URL/DB_NAME).
- This DB is the expected, fully-populated ERP database — **30 collections** with real data — NOT a fresh/empty database.

## 3. `comisiones_vendedor`
- **Collection does not exist** in production (0 docs, absent from the 30-collection list). No commission %/“pagada” configs have ever been written. Even if sales had vendedor values, commission columns would read 0/unpaid until this collection is populated via `POST /api/estadisticas/vendedores/comision`.

## Code verification (eph sandbox, active run source)
Confirmed the deployed code handles `vendedor` correctly and consistently — this is NOT a code regression:
- Read endpoint `server.py:2904 estadisticas_vendedores` iterates `CANALES_COMPRA=(finca,ciudad,refrigerar,congelar)`, and **intentionally skips any sale with empty vendedor** (`vend = (v.get("vendedor") or "").strip(); if not vend: continue`). It also skips system-origin rows (asignacion_destino etc.).
- Write path `server.py:1873 _create_v` persists the full `VentaIn` (which includes `vendedor`) via `payload.model_dump()`.
- Frontend sale forms (`Ventas.jsx`, `VentaRapida.jsx`) now render a **required "Vendedor *"** field and send it on POST.

## Root cause
Production has **no vendedor-tagged sales** and **no `comisiones_vendedor` collection**, so `GET /api/estadisticas/vendedores` correctly returns an empty result. The sales records themselves are intact and the backend is on the correct database. The most plausible history: the `vendedor` field / "Estadísticas de vendedor" feature is newer than the bulk of the sales data, so historical sales (Jun–Oct) were saved without a seller, and no sale has been recorded with the field filled since. There is no evidence of data loss or of a prior seller field being dropped.

## Suggested fixes (NOT applied)
1. **User — data (change_mongo_data):** For past sellers to appear, existing sales documents must be backfilled with the correct `vendedor` per sale (only the user knows the right seller for each historical record). This is a data edit, not a code fix.
2. **User — going forward:** Register sales with the now-required **Vendedor** field filled; those will immediately populate the module for the selected month. Configure commission % via the module (writes `comisiones_vendedor`).
3. **Code (E1) — optional sanity check:** Code was verified correct in sandbox, but if the user insists the module showed data before this deploy, E1 should confirm no earlier build wrote the seller under a different field name and that the edit path can’t silently blank `vendedor`. No regression was found in the current source.
